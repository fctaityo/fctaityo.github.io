v4.2では、Reference Implementation（実証実装）の進行表示を「現在地を見る」だけのRailから、Current Node（現在ノード）を起点に詳細をInline Expand / Collapse（直下開閉）できるBuild Telemetry（構築管制盤）へ拡張しました。

Why Changed

従来のParallel Project Viewは「どの段階にいるか」を素早く確認する用途には有効でしたが、RI#1がなぜPARTIALなのか、次に何が必要なのか、Runtime（実行時）やEvidence（証拠）がどの状態なのかをWebsite上では追えませんでした。v4.2では、進行Railを壊さず、その直下に公開可能なTelemetryを展開できる構造へ変更しました。

What Changed

RI#1 Inline Telemetry

RI#1の横ライン全体を操作対象とし、Current Node付近を含む自然なクリック領域から詳細管制盤を直下展開。

Current Node → Energy Beam

現在地の発光PulseからEnergy Beamを通してTelemetryを起動。Panel Border Trace、Scan、Card Bootを連動させた。

Formal IVM Public Projection

Website用の値を手入力せず、Formal IVMから公開可能項目だけを投影。架空の進捗率やEvidence数を実装値として持ち込まない。

Guide / Operator Separation

Parallel側のGuideとTelemetry内のOperatorを別役割・別Cropとして配置し、開閉状態に応じた見せ方を整理。

FOUNDRY PULSE Refinement

Repository、Project State、RI#1、Acceptance、Runtime、Formal RVを横方向へ均等配置し、Current Snapshotの情報密度を改善。

Interaction & Accessibility

Native button、ARIA、Enter / Space、Escape Close、Focus復帰、prefers-reduced-motionへ対応。

Publication Boundary

  • Formal IVMからPublic Projection（公開投影）した項目のみWebsiteへ表示する。
  • Baseline ID、Commit SHA、Run ID、Session ID、Internal Path、Raw EvidenceはWebsiteへ表示しない。
  • モックで用いた85%、72%、42%、Evidence 12 / 28、Test RUNNING、仮更新日時などの架空値は実装へ持ち込まない。
  • Freshness Warningは隠さず、Formal Snapshotが古い場合はその状態を表示する。

Preserved

  • v4.1のHuman × AI責務境界とFOUNDRY PULSEの役割
  • Project State `Published` とRuntime Acceptanceを混同しない表示
  • RI#1 / RI#2 / WEB / CORE / RI#3のParallel Project構造
  • Public Documentationへの導線
  • HumanがWebsite Commit / Pushを行うPublication Boundary

  • Current Node Pulse / Energy Beam / Telemetry Boot sequence
