# BZ-20260731-016 Partial SourceをCanonical Sourceとして扱う

- Date: 2026-07-31
- Status: Recorded
- Category: Source / Change Management

## 症状

既存成果物を変更する際に、正本の一部だけを取得した状態で不足部分を生成・補完し、その結果を正本に基づく変更案として扱ってしまう。

変更対象は反映されているように見えるが、取得できていなかった既存内容、リンク、構造、ID、参照関係などが失われる。

生成結果だけを確認している場合、変更対象外の消失を検出できない。

## 発生条件

以下の条件が重なると発生する。

- 対象ファイル全体を取得していない
- 取得済みの断片をファイル全体だと誤認する
- 不足部分を会話履歴、記憶、推測、別資料で補完する
- 正本へ変更を適用せず、似た成果物を新しく生成する
- 変更後の完成形だけをレビューする
- 正本との差分をEvidenceとして確認しない
- 変更対象外を品質保証の対象に含めない

## Root Cause

Root Causeは、Canonical Sourceを「取得元」だけで判断し、「取得完全性」を確認しなかったことである。

GitHubから取得した情報であっても、対象ファイルの一部しか取得していなければ、変更元として必要なCanonical Sourceは成立していない。

その状態で不足部分を補完すると、変更案は正本へのPatchではなく、正本を参考にした再生成物へ変わる。

さらに、変更要求を「新しい内容を含む成果物を作ること」と解釈し、変更対象外を維持する責任をScopeから外したことで、既存内容の消失が見逃される。

## 影響

- 変更対象外の本文が消失する
- 既存リンクやNavigationが失われる
- ID、参照先、表構造が変化する
- Configuration ItemやAudit記録が欠落する
- WorkflowのNodeやEdgeが意図せず変化する
- 見た目上は要求内容を満たすため、異常の発見が遅れる
- Repositoryへ反映した時点で、再生成物が新しい正本になる

## 検出方法

次を確認する。

1. 対象ファイルを先頭から終端まで取得したEvidenceがあるか
2. 変更案が取得した正本を変更元としているか
3. 正本と修正版の差分が存在するか
4. 差分が要求された変更Scopeだけに限定されているか
5. 変更対象外の見出し、リンク、ID、参照関係が維持されているか
6. Repository反映後にGitHub最新版を再取得したか

完成形だけを読んでも、この障害パターンは十分に検出できない。

## 再発防止

- GitHub最新版をCanonical Sourceとして取得する
- 対象ファイル全体の取得を確認する
- 取得できない場合は、別の情報源で補完せず停止する
- 既存成果物を再生成しない
- 正本を保持したまま必要な変更だけを適用する
- 変更前後の差分をEvidenceとしてレビューする
- 変更対象外の維持を明示的な確認項目にする
- Repository反映後に正本を再取得して確認する

## 教訓

**正本の一部は、正本ではない。**

**要求された内容が追加されていても、既存内容が失われていれば変更は失敗である。**

**完成形ではなく、正本との差分をレビューする。**
